}

============================================================
B3-1: Explain without an index
============================================================
> db.movies.find({ genre: "Drama", rating: { $gte: 8 } }).explain("executionStats")

winningPlan.stage                 : COLLSCAN
executionStats.nReturned          : 2        (Silent River, Morning Song)
executionStats.totalDocsExamined  : 8

Result: COLLSCAN reads all 8 documents to return 2.

============================================================
B3-2: Compound index in the right order (index name: genre_1_rating_-1)
============================================================
> db.movies.createIndex({ genre: 1, rating: -1 })
genre_1_rating_-1

> db.movies.find({ genre: "Drama", rating: { $gte: 8 } }).explain("executionStats")

winningPlan.inputStage.stage      : IXSCAN   (indexName: "genre_1_rating_-1")
nReturned                         : 2
totalDocsExamined                 : 2
totalKeysExamined                 : about 2-3

Note: Equality field (genre) first, range field (rating) second is the
efficient order for this query.

============================================================
B3-3: Compare with a poorly ordered index
============================================================
> db.movies.createIndex({ rating: 1, genre: 1 })
rating_1_genre_1

> db.movies.find({ genre: "Drama", rating: { $gte: 8 } }).hint({ genre: 1, rating: -1 }).explain("executionStats")

winningPlan.inputStage.stage      : IXSCAN   (indexName: "genre_1_rating_-1")
nReturned                         : 2
totalKeysExamined                 : about 2-3

> db.movies.find({ genre: "Drama", rating: { $gte: 8 } }).hint({ rating: 1, genre: 1 }).explain("executionStats")

winningPlan.inputStage.stage      : IXSCAN   (indexName: "rating_1_genre_1")
nReturned                         : 2
totalKeysExamined                 : higher than the well-ordered index

Result: Both queries return the same 2 movies, but the poorly ordered index
rating_1_genre_1 has to look at every movie rated 8 or more (including the
Action movie Iron Gate, 8.1) before checking the genre, so totalKeysExamined
is higher. With only 8 documents the gap is tiny; with millions it is very
large. Compare the two numbers, not the absolute values.

============================================================
B3-4: Drop the poorly ordered index
============================================================
> db.movies.dropIndex({ rating: 1, genre: 1 })
{ nIndexesWas: 3, ok: 1 }

============================================================
B4-6: Disaster-recovery table and backup practices
============================================================
Failure situation                 Recovery action
-------------------------------   ---------------------------------------------------------
Accidental deletion               Restore the collection from backup using mongorestore.
Primary server failure            Replica set elects another member as primary (failover).
Database corruption               Restore the database from a valid backup.
Hardware failure                  Replace the hardware and restore the data from backup.
Accidental data modification      Restore from backup, or use point-in-time recovery if available.

Three good backup practices:
1. Take regular backups.
2. Store backup copies in a separate location or in the cloud.
3. Test backup restoration regularly.
